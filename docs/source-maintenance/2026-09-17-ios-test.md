# iOS diagnostics test candidate

This follow-up to the source-maintenance audit adds a private iOS build 3; the published v0.1.1/build 2 release remains unchanged. Foundation and dependency pins are unchanged. No new public release is authorized.

- Options groups diagnostics, touch controls and display settings, with an iPad-anchored export share sheet. [Export contents and instructions](../DIAGNOSTICS.md).
- Control appearance uses darker colored surfaces, thin accent strokes, continuous corners and pressed/latched emphasis. Input masks, touch targets, layout preferences, gas latch and drift behavior are retained.
- The [generic empty blue kart icon](../design/ios-kart-icon.md) contains no character imagery. Asset-only changes now rerun asset compilation during incremental builds.
- Simulator attract-mode testing exposed a 64-bit oscillator allocation defect: `MainInit_JitPoolsNew` reserved the original 24-byte item size while native `ParticleOscillator` is 32 bytes. It now uses `sizeof(struct ParticleOscillator)`. The 32-bit size remains 24 bytes. Pool diagnostics include allocated/required stride. This is a concrete undersized allocation fix, not reporter acceptance of issue #36.

## Validation boundary

The pre-fix diagnostic build stopped at frame 3026, level 35, during the Simulator attract demo with `invalid_pool reason=oscillator-free-head`. The corrected build passed that sequence and reached frame 3993/level 39. These are Simulator observations, not physical gameplay acceptance.

The macOS runtime suite passes 27/27 tests. Logger tests cover retention, interrupted sessions and size rotation. New Foundation export tests exercise metadata, privacy-pattern filtering, current/previous/missing logs, bounded header/tail snapshots and concurrent logging. Device and Simulator builds compile. The Simulator share sheet saved a readable report into Files and removed its temporary copy after completion. The compiled iPad icon was decoded and visually verified as the empty kart.

Physical build signing, install/startup, before/after durable-data verification and final candidate identity are recorded in the PR and private deployment evidence after packaging. Manual touch feel, a completed race, and the original reporter's reproduction are separate acceptance steps.

The iPad's Documents and Library were backed up in full, with 18 content hashes verified after restoration into a separate local directory. These backups are on the same physical disk, not a copy on independent storage.

The installed baseline was verified as source `d095cadfb62d4bddc5738f731104f00c81d3ec19`, version 0.1.1/build 2. Its original unsigned IPA/source archive and the established signing profile remain preserved privately. Recovery is an in-place install of that baseline re-signed for the same bundle/team/keychain identity. Do not uninstall or overwrite current saves as a rollback shortcut. Private recovery commands and paths are recorded outside the repository; no game data, device identifiers or signing material are published.
